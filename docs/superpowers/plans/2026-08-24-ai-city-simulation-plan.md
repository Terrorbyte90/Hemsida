# AI City Simulation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a polished, autonomous five-agent 3D city simulation as a new “Simulering” page without changing the rest of the site.

**Architecture:** Static HTML/CSS/JavaScript with Three.js loaded from the existing CDN convention. A deterministic client-side simulation guarantees continuous behavior; an OpenAI-compatible local Qwen adapter enriches planning and conversation when available.

**Tech Stack:** HTML, CSS, browser JavaScript, Three.js r128, existing GLB assets, localStorage, OpenAI-compatible HTTP API.

**Spec:** `docs/superpowers/specs/2026-08-24-ai-city-simulation-design.md`

## Global Constraints

- Preserve all existing pages and visual language.
- No API key or private endpoint credential may be committed.
- The page must remain useful when WebGL, network, or Qwen is unavailable.
- Every agent must have a distinct profile, needs, activity, and relationship state.

### Task 1: Add navigation entry

**Files:** Modify `index.html`, `projekt.html`, `min-varld.html`, `ornith.html`, `kurser.html`, `poddar.html`, `rostlabb.html`, `forskning.html`, `om-mig.html`.

- Add `<a href="simulering.html">Simulering</a>` beside the existing “Min värld” link in each site navigation.
- Keep existing active-page semantics unchanged.
- Verify with `rg -l 'Simulering' *.html` and count all top-level pages.

### Task 2: Build agent state and local-model adapter

**Files:** Create `simulering-agents.js`.

- Export `CITY_AGENTS`, `createSimulationState()`, `tickAgents(state, minutes)`, `askQwen(agent, context, endpoint)` and `formatAgentThought(agent)`.
- Model needs as numeric values, utility choices as deterministic actions, destinations as named city locations, and relationships as symmetric scores.
- Validate Qwen JSON response against allowed action names; reject malformed responses and return `null` so the caller uses local utility behavior.
- Store only endpoint preference in localStorage; never store secrets.

### Task 3: Build page shell and visual system

**Files:** Create `simulering.html`, `simulering.css`.

- Add semantic header, 3D stage, agent rail, selected-agent panel, event stream, city-law panel, controls, and text fallback.
- Include controls for pause, speed, time-of-day, weather, and local Qwen endpoint.
- Implement responsive desktop/mobile layouts, keyboard focus, and reduced-motion CSS.

### Task 4: Build 3D scene and simulation loop

**Files:** Create `simulering.js`.

- Create a Three.js scene with roads, plaza, homes, library, school, workshop, town hall, trees, streetlights, water, sky, fog, rain/snow particles, sun/moon lighting, and five visible avatars.
- Animate agents along deterministic paths between locations, update lights/weather/time, and render status labels/events.
- Add raycasting for agents and places, orbit/drag camera, resize handling, and WebGL/text fallback.

### Task 5: Add autonomy UI and civic interactions

**Files:** Modify `simulering.js`, `simulering.html`.

- Periodically call Qwen for one selected agent at a time with abort timeout; merge valid plans into activities and add a visible thought/event.
- Allow conversation prompt with selected agent; display model response or explicit local fallback.
- Implement proposed laws, vote totals, enacted/rejected state, and event log entries generated by the simulation.

### Task 6: Verify and deploy

- Run a local HTTP server from `Hemsida`.
- Browser-test desktop and mobile widths, console errors, WebGL load, controls, model fallback, and navigation.
- Run static checks for five profiles, locations, laws, and all navigation links.
- Commit only Hemsida changes, push the existing branch, and verify the live GitHub Pages URL and page asset responses.
